**Self-hosted** web app to track a personal investment portfolio. Everything is stored in SQLite and runs on your own machine or a home server with Docker.

Market quotes are optional: without API keys you enter prices yourself. The interface is in Spanish.

## ✨ Features ✨

- **Portfolio**: summary, per-asset page with average price and performance split into asset effect and currency effect, and investment plans.
- **Finances**: expenses, income, monthly payments, cash accounts, dividends, fixed income and bonds.
- **Spanish taxation**: sales with FIFO, the two-month rule and loss offsetting; annual report in CSV and HTML.
- **Metrics**: TWR, XIRR, drawdown, volatility and comparison against indices.
- **Crypto**: stablecoins, trades, conversions, staking and earn. Read-only wallet linking (Bitcoin by address —Legacy, SegWit or Taproot—, xpub/ypub/zpub —including Taproot accounts— or single public key, with automatic format detection; Ethereum and BNB Smart Chain by address or public key; Solana and XRP) that imports on-chain movements into Transactions, plus a **Seguimiento** page with the balance, euro value and latest movements of your own wallets and of third-party ones you follow, with optional Telegram alerts on every new movement; addresses and xpubs are stored encrypted and never shown in full.
- **Operations**: automatic backups, Telegram alerts and commands, optional two-step login with a code sent by Telegram, HTTPS enabled from the app itself, and an iOS Shortcut to log expenses from your phone.
- **Self-updating**: `docker-update.sh` checks that the new version answers on `/api/health` and rolls back to the previous image if it does not.

## 🖥️ Requirements

| To | You need |
|---|---|
| **Use it** | Docker with Compose v2 (Linux server recommended), or Python 3.11+ without Docker |
| **Develop** | Python 3.11+ (CI tests 3.11, 3.12 and 3.13) and Node.js 20 for the frontend linter and tests |

## 📦 Installation guide ⚙️

### Option 1: Docker (recommended)

```bash
git clone https://github.com/FranciscoFdez05/PorfolioManager.git
cd PorfolioManager
./docker-setup   # creates .env, generates SECRET_KEY, asks for credentials and port, starts the stack
```

The stack runs the web app, a **worker** service with the same image for background tasks (automatic backups, snapshots, Telegram and alerts for prices, wallets and Satoshi's coins, so they never take gunicorn's threads), the Caddy proxy and the update watcher. Run it as your normal user, without `sudo`. The app is served at `http://localhost:5050` (or `http://<SERVER_IP>:5050` from another device on the LAN). Data is kept in `data/`, `logs/` and `API/`.

> [!WARNING]
> Out of the box the app is served over plain HTTP, so the password and session cookie travel unencrypted. Before using it from another device, enable HTTPS in **Ajustes › Seguridad › HTTPS**. See [SECURITY.md](SECURITY.md).

To update an existing installation:

```bash
./docker-update.sh              # git pull, build, start and health check, with automatic rollback
./docker-update.sh --sin-pull   # same, without git pull
```

### Option 2: from source

```bash
git clone https://github.com/FranciscoFdez05/PorfolioManager.git
cd PorfolioManager
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python python/server.py   # http://localhost:5050
```

### Environment variables

Secrets live in `.env` (copy `.env.example`; `./docker-setup` does it for you). The rest of the settings are in `config.ini`.

| Variable | Description | Required | Default |
|---|---|---|---|
| `SECRET_KEY` | Signs sessions and encrypts stored API keys and credentials | Yes | Generated by `docker-setup` |
| `LOGIN_USERNAME` | Initial user, used only on first start | Yes | `admin` |
| `LOGIN_PASSWORD_HASH` | Hash of the initial password (`docker-setup` generates it) | Yes | empty |
| `FINNHUB_API_KEY`, `EODHD_API_KEYS`, `ALPHA_VANTAGE_API_KEYS` | Market data keys; normally set in Ajustes › API instead | No | empty |
| `ETHERSCAN_API_KEY` | Etherscan v2 key to read Ethereum wallets (BNB only with a paid Etherscan plan); can also be saved from the wallets screen, a tracking's **Editar** window or **Ajustes › API** (a single key: saving another replaces it) | No | empty |
| `NODEREAL_API_KEY` | NodeReal key, a free-plan alternative to read BNB Smart Chain wallets; choose the BNB API in **Ajustes › API › Estado de las APIs**. Can also be saved in **Ajustes › API** (a single key: saving another replaces it) | No | empty |
| `TZ` | Container time zone (logs and backups) | No | `Europe/Madrid` |
| `PORT` | HTTP port; overrides `config.ini` | No | `5050` |
| `PUID` / `PGID` | User and group the container writes as (Linux) | No | Set by `docker-setup` |

## 📋 Usage guide 🕹️

1. Open `http://localhost:5050` and sign in with the credentials you chose in `docker-setup`.
   On the first run `docker-setup` asks how to create the account: **1** from the web, **2** in the terminal, **3** quit. A typo just asks again. With the web option it prints the `/setup` address and a one-time verification code (also in `data/tmp/alta-inicial.txt` and the container log), so nobody else on the LAN can claim the account first.
2. Add your assets and operations. Without API keys, enter prices manually.
3. Optionally add Finnhub, EODHD or Alpha Vantage keys in **Ajustes › API** to get automatic quotes.
4. Enable HTTPS in **Ajustes › Seguridad › HTTPS** if you access it from other devices.
5. Optionally set up Telegram in **Ajustes › Telegram** (alerts and commands such as `/estado`, `/cartera`, `/backup`).
6. Once Telegram works, you can turn on two-step verification in **Ajustes › Cuenta**: each login asks for a code sent by the bot, and a 6, 12 or 24-word recovery phrase lets you in if you lose access to Telegram.
7. To import a wallet's movements, open **Cripto › Transacciones › ··· › Wallets enlazadas**, paste its public address (or the xpub/ypub/zpub for Bitcoin, or a public key for Bitcoin, Ethereum and BNB; the format is detected automatically) and press **Sincronizar**. You can also link them straight from a crypto asset, in the **Nuevo activo** and **Editar activo** windows: one or more addresses or public keys are linked as your own wallets, associated with that asset and grouped in a tracking named after it (nothing is created if a line is invalid). Never paste a private key or seed phrase: the app rejects them. Linking requires a random `SECRET_KEY` of at least 32 characters; the network endpoints (Esplora, Solana RPC, XRPL) can point to your own node in the `[wallets]` section of `config.ini`. If the Bitcoin Esplora server does not connect, answers 5xx or rate-limits, the same request goes to `[wallets] esplora_url_respaldo` (`https://blockstream.info/api` by default) and keeps going there for a few minutes; set it to the same URL as `esplora_url` to disable the fallback.
8. **Cripto › Seguimiento** groups linked wallets into trackings: one tracking can hold several addresses, xpubs or public keys, even on different networks (the accounts of a Ledger, or all the wallets of a person you follow), and its card shows the combined balance, euro value and recent movements. Add more with **Añadir wallet** on its card, or pick an existing tracking when linking; all the wallets in a tracking are either yours or third-party. **Editar** on a tracking renames it, renames each wallet or changes its crypto asset, removes wallets and adds new addresses or public keys in one go; the network and address of a linked wallet cannot be changed (remove it and add the new one). **Dejar de seguir** (**Desenlazar todas** on your own trackings), in a tracking's detail, unlinks all its wallets at once; transactions already imported stay. A Bitcoin public key also counts its P2PK outputs (coins paid to the bare key, such as the 50 BTC rewards of the first blocks), read from Esplora by script hash. Click a tracking to open its detail (each wallet with its own alerts and actions, totals, the merged history loaded 100 at a time with filters and block-explorer links, a **Ver en gráfico** button that draws the movements shown in the table (same filters and dates) as a flow graph like the one in Cuentas —one circle per address, named by its wallet alias or address-book nickname, and one arrow per origin → destination as thick as the amount moved, one coin or token at a time; imitations are left out unless that filter is on—, a **UTXO viewer** for Bitcoin wallets —own or third-party— that draws every unspent output as a treemap block sized by its amount and coloured by its age, with unconfirmed ones striped and a click showing its transaction, output, address, block height and confirmations, a **token viewer** for Ethereum and BNB wallets that reads the current balance of every ERC-20/BEP-20 token on demand from the API chosen for that network (with Etherscan, one call per token, up to `[wallets] max_tokens_visor` in `config.ini`, 40 by default) with its contract status and the crypto, enabled stablecoin or **tokenized ETF** from Activos matching its symbol, valued in euros at that asset's price (approximate for tokenized ETFs; imitations get no asset or value), and arrows to move to the previous or next tracking). What the detail reads (history, tokens and UTXOs) is stored per wallet, encrypted with `SECRET_KEY`, in `API/wallets_lecturas/` (ignored by git and left out of backups, since reading the network rebuilds it): opening a tracking again shows it at once with its load date while new movements are fetched, unless the last read in that browser tab is under 2 minutes old; a network failure keeps what was stored, **Volver a leer** replaces it, and unlinking a wallet deletes it. Without a valid `SECRET_KEY` nothing is stored. In Transactions, movements are imported under the tracking's name. You can also follow third-party wallets (only tracked, never imported or added to your total). **Carteras conocidas…**, in the **⋯** menu next to **Enlazar wallet**, searches a catalogue of public wallets bundled with the app (exchanges such as Binance, Coinbase, Bitvavo, Kraken, OKX or Bybit on Bitcoin, Ethereum, BNB, Solana and XRP; Satoshi's genesis address and early-block public keys; Vitalik Buterin, Donald Trump and World Liberty Financial; Mt. Gox, US government and El Salvador holdings; Tether, funds and more) by name, alias, category or address: tick the addresses to follow (one per network by default; those already followed are greyed out) and **Seguir las marcadas** opens the linking window with them filled in as a third-party tracking, ready to link. The catalogue is a JSON file inside the project (`python/core/datos/carteras_conocidas.json`, copied once from the exchanges' proof-of-reserves lists, eth-labels and other public sources, each entry naming its source); the app never downloads it. From the same window you can add your own entries, edit any of them (your version replaces the bundled one until you press **Restaurar**) or hide them; your changes are stored encrypted in `API/carteras.key` with the same `SECRET_KEY` as the wallets. Inside the catalogue, the **Satoshi Nakamoto** entry has a **Todas sus monedas** block that shows Satoshi's real balance (~1.1 M BTC): it starts from a snapshot of the ~22,000 coins he mined (Patoshi blocks) that are still unspent, bundled in `python/core/datos/satoshi_monedas.csv.gz` and regenerated with `tools/generar_satoshi_monedas.py` (Electrum, slow on purpose so public servers do not block the IP). With **Vigilar bloques nuevos** on, the server downloads every new Bitcoin block (about 144 a day, ~210 MB) from the Esplora server in `[wallets] esplora_url`, checks whether it spends any of those coins, subtracts them from the balance and, with **Avisos por Telegram**, sends an alert; **Revisar ahora** checks the pending blocks at once. Its state is kept in `API/satoshi_vigilancia.json` (ignored by git). Choose how often they are checked in the background (from 5 minutes to once a day, 15 by default) and turn on Telegram alerts per wallet, optionally only above a minimum amount; the "Movimientos en las wallets" category in **Ajustes › Telegram** must be on as well. The **Avisos Telegram** button, when linking or in **Editar** (for the whole tracking), opens a movable window with every option: which movements alert (received, sent, between own addresses, tokens), a minimum in coin units or in euros, an alert when the balance drops below or rises above a limit, an alert when a wallet moves again after N idle days, **suspicious movements** that alert even when the filters above would drop them (a send to an address never seen in the address book or the movements read, the wallet left with 10 % of its balance or less after a send, dust under 1 € or zero-value tokens, an address that imitates a known one —same start and end, the address-poisoning trick— and 3 or more sends between two checks, plus **Tokens imitación**), grouping each check's alerts into one message, a maximum of messages per check, and quiet hours (server time, `TZ`; anything during them is sent together when they end). Token alerts use the same per-contract decision as the history and the import: a token from a contract you verified says "token verificado", and one from a contract you marked as an imitation (or detected as one) never alerts as a normal movement, also when it arrives again later; it only alerts as suspicious with **Tokens imitación** on, or when it comes from a lookalike address. One-click profiles at the top fill it in (**Todo**, **Seguridad**: sends, suspicious movements and a 90-day wake-up alert, **Solo grandes**: movements of 1,000 € or more and drained wallets) and the balance and delivery options stay folded under **Más opciones**. In a tracking's detail, the **Sospechosos** and **Despierta** buttons next to each wallet's alert switch turn those alerts on or off in one click (and turn the wallet's alerts on); the **Todas las wallets** row above the list does the same for every wallet of the tracking at once (Telegram alerts, **Sospechosos**, **Despierta** and **Actualizar todas**), keeping the rest of each wallet's settings. While wallets are being read (updating one, a tracking or all of them, syncing, history, UTXOs or tokens) a small progress bar in the bottom-right corner shows how many are left, the one being read and an estimate of the time remaining. There is no limit on the number of linked wallets, but each one is one more request on every check, so free API limits (Etherscan, Solana) are what really caps it. The **Direcciones** button opens your address book: mark addresses as yours or third-party and give them a nickname, and search it by nickname or address. Each row is a summary: click it to unfold the address, its read data, alerts and latest movements, and the actions on it. Each address shows its balance: linked wallets show the last balance read (plus the tokens already read in the detail) and their euro value, and manually marked addresses read their native-coin balance from the network on demand with **Ver saldo** (it is not stored). **Sincronizar** also imports what your wallet paid in network fees without moving the coin (sending a token, approvals, swaps, failed transactions on ETH, BNB, SOL and XRP) as an **Entre wallet** row that only deducts the fee from that coin's position, and a receipt from an address of yours deducts its transaction's fee, except on Bitcoin and tokens. In a movement's detail, a single transaction of your own wallet can be marked **Entre mis wallets** or as received/sent, whatever its address says: what you bought on an exchange and withdrew to your wallet is then not added to the position a second time and only its fee is deducted. **Entre mis wallets** also adds both addresses to **Direcciones** as yours; untick the option for the other address if it belongs to an exchange, because otherwise all its movements, past and future, count as between own wallets without verification. Removing the mark takes out the addresses it added, unless another mark still needs them or you have given them a nickname. Clicking a row in **Cripto › Transacciones** opens the same window; if its movement cannot be found (a row typed by hand, or one the network no longer returns), it shows the row's data with **Editar**. The fee is proposed from the network on ETH, BNB, SOL and XRP and you can change it; on Bitcoin and on tokens you type it, and on Bitcoin only mark it if everything moved is still yours (change to an address that is not linked makes the amount inexact: link that wallet by xpub). **Vincular a seguimiento** turns an address marked as yours into a wallet of a new or existing tracking: it is watched from then on, its native-coin balance adds to your total and it enters the Watchlist and **Sincronizar**. **Cambiar de seguimiento** moves a linked address to another tracking, keeping its readings and alerts, and **Sacar del seguimiento**, after asking for the web access password, returns it to the address book as yours, losing them. **Editar apodo** on a linked wallet renames its tracking. Linked wallets are masked; **Ver completas** shows their full addresses after asking for the web access password, and they are hidden again with **Ocultar** or when the window is closed. A movement to or from an address marked as yours counts as **between own wallets** in the history, the alerts and Transactions (instead of sent or received), and the counterparty shows its nickname; the addresses of your own linked wallets count as yours without marking them, and a manual mark overrides that: all the addresses of a public key, and the used addresses of an xpub, which are found on each read and appear in **Direcciones** (a transaction only counts as between own wallets when all its counterparties are yours). Money coming in from third parties must be verified by hand: it shows as **Pendiente de verificar** in the tracking and is neither imported nor added to the position until you open the movement and choose **Entrada real** or **Entre mis wallets** (rows imported as received before this existed, and imported rows whose verification you remove, stay in **Cripto › Transacciones** as **Pendiente de verificar** and do not count; choosing **Recibida** when editing the row also verifies it). The background read of each wallet is limited by `[wallets] plazo_vigilancia_segundos` (`WALLETS_PLAZO_VIGILANCIA_SEGUNDOS`, 300 by default) instead of `plazo_segundos`, and when it fails the card shows why. You can also mark the counterparty straight from a movement's window (**Es mía** / **Es ajena**). Rows already imported into Transactions with that counterparty are relabelled when you mark it, unmark it, or link or unlink one of your wallets. The address book is stored encrypted together with your own wallets in `API/wallets.key` (needs `SECRET_KEY`). Third-party wallets you follow are public addresses of others, so they go unencrypted to `API/wallets_ajenas.json` (ignored by git) and can be followed without `SECRET_KEY`; any that were in `wallets.key` move there on the next save.
   Backups always carry linked wallets (wallets, address book, marks, tokens and your catalog entries) inside the encrypted package, protected with the backup password or, if there is none, the web login password; **Incluir las claves de API en las copias** in **Ajustes** only decides about the API keys. A manual export only carries them when it has a password. Restoring re-encrypts them with this server's `SECRET_KEY`, and each wallet's first check after that only records what is there, without alerts. A card warns when background checks fail, when more movements happened between checks than could be read (each check reads 25, then up to 200 if none is known) and when suspicious alerts could not be delivered (they are retried on the next check). Third-party wallets are checked at most every `[wallets] ajenas_cada_minutos` (6 hours by default), whatever the interval chosen. **Sincronizar** warns when it hits `[wallets] max_movimientos`, because older movements stay out of Transacciones. The total only counts each network's coin, not tokens; the coin's price comes from the ticker set in **Análisis › Seguimiento**, the wallet's asset or a crypto asset with the network's symbol in the active portfolio, and without any of them a minimum in euros does not filter alerts. `tools/comprobar_carteras_conocidas.py` lists catalog addresses that are empty or unreadable, for manual review.
9. Ethereum and BNB tokens (ERC-20/BEP-20, memecoins included) are imported into the crypto asset or enabled stablecoin with the same symbol; a token with no matching asset is reported, not imported. Because anyone can create a token with any symbol, the **Token** column of a tracking's history shows each token's contract (with a link to Etherscan/BscScan and a colour dot per contract) and its status: **Sin verificar**, **Verificado** or **Imitación**; in the history, the actions on each token are in the **···** menu at the end of its row (**Ver ↗** stays outside), and each option acts on the contract of its own row even after changing the filter or the dates. Press **Verificar** on the genuine contract (check it on the explorer or the project's website first): from then on any other contract with that symbol on that network is marked as an imitation and is no longer imported, and the **Imitaciones** filter lists them. **Quitar** undoes it. Without you doing anything, a contract listed in the public Uniswap or CoinGecko token lists already shows as **Verificado** (and any other contract with its symbol on that network as an imitation, also when importing); you can **Confirmar** it, which pins it even if the lists change, or mark it with **Es imitación**. What you confirm overrides the lists. They are downloaded whole once a day (no third party sees which tokens you hold) and set in `[wallets] listas_tokens` in `config.ini`; leaving it empty turns automatic recognition off. Detection only suggests; you have the final say on each contract: **No es imitación** overrides a detected imitation (from then on it is imported by its symbol, like an unverified token), **Es imitación** marks an unverified token you know is spam (it is no longer imported), and **Deshacer** goes back to automatic detection. Your marks override the rules below. The confirmation shows the full contract, warns about signs of a copy (other contracts with the same symbol among the movements read, unusual characters in the symbol, a token you have only ever received) before you press **Verificar** in it. Symbols are compared without accents or marks, so a token named after the network's coin (a fake "ETH", or "ĖŢḤ") is detected as an imitation, and even if you mark it as not one it is never added to the network's coin. A movement of a network's own coin (BTC, ETH, BNB, SOL or XRP) shows as **BTC real · moneda de la red**: it has no contract, so it cannot be an imitation. Solana SPL tokens and XRP Ledger issued currencies are not read, so they never appear as that coin. Verified and marked tokens are stored encrypted together with the wallets. Apart from that status, **Es sospechoso** in the **···** menu (in the history and in the token viewer) labels a contract you find odd even though no list or rule flags it; it is only an amber **Sospechoso** label for you, it does not change the status or what is imported, and **No es sospechoso** removes it. In the token viewer, a token with no matching asset in Activos offers **Poner ticker de precio**: choose the quote provider (TradingView by default, Finnhub, EODHD, Yahoo Finance or Alpha Vantage) and the ticker (e.g. `BINANCE:PEPEUSDT`), which you can type or find with the **Buscar** button, that previews each result's price and daily change as when adding an asset; it is checked against the provider before saving, values the token in euros from then on (also over an asset matched by symbol) and can be changed or removed from the same menu. The same option is in the **···** menu of each row or card of the Watchlist's **Seguimiento** list, where it also covers the coin of each network (a ticker set there only quotes it in that list). Every token seen in a wallet (contract and symbol only, never balances) is remembered encrypted with the wallets, up to 2,000, for the **Seguimiento** list of the Watchlist, which shows the coin of every network you follow plus those tokens (imitations excluded), quoted with their ticker or their asset. In the Watchlist the source filters (**Portfolio**, **Operaciones**, **Nuevos**, **Seguimiento**) now show one source at a time.
10. **Ajustes › Módulos** chooses which modules appear in the menu and which one opens at startup (the **Principal** column, saved per portfolio). The main module cannot be hidden until you choose another one; the top metrics bar has its own switch in the same screen.

```bash
docker logs -f PorfolioManager   # follow the logs
docker logs -f PorfolioManager-worker   # background tasks
docker compose down              # stop the stack
```
